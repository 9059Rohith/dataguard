# Security model

Threats addressed: accidental bad inputs, duplicate deliveries, unauthorized mutation via HTTP, oversized bodies, path traversal through Airflow artifact input, SQL injection through values, interrupted publication, and unsafe container privileges.

Privileged HTTP routes fail closed unless `DATAGUARD_TOKEN` contains at least 32 non-whitespace characters. Comparison uses constant-time byte comparison, including malformed non-ASCII header input. Use randomly generated tokens from Secrets Manager/Kubernetes Secret, terminate TLS before the API, rotate tokens with an operator rollout, and never place tokens in query strings or dashboard storage. This single shared operator credential has no individual attribution or tenant RBAC. Database connections are parameterized through SQLAlchemy; dynamic SQL in initialization is restricted to fixed UPDATE/DELETE trigger names.

Public routes expose aggregate partition identifiers, counts and operational metrics inside a private deployment boundary. Raw financial records, staged source documents and row diagnostics require authorization. Place all endpoints behind a VPN or restricted ingress; do not expose this operator console as a public multi-tenant service. The frontend writes values with textContent and restricts scripts with CSP. An 8 MB body cap is enforced for known-length and streamed HTTP requests; also configure connection/rate/time limits at ingress. Database credentials and API tokens are never logged by application handlers. Infrastructure provider state and shell history still require access controls.

Staging UPDATE and DELETE are blocked by database triggers, plus SHA256 detects content identity for idempotency. This is not tamper-proof against a superuser who can disable triggers, TRUNCATE, or modify heads/materialized rows. Use separate migration and runtime roles and grant runtime only SELECT/INSERT on batches, required operations on attempts/heads/gate, and INSERT/SELECT on published tables. The demo's bootstrap uses a DB owner for convenience; the Terraform starter currently injects managed RDS admin credentials for bootstrap and must be split into migration/runtime roles before a production rollout. Never grant a public caller direct database access.

Container runs UID 10001 with no capabilities, no privilege escalation, a read-only filesystem and bounded resources. K8s denies ingress/egress beyond named operators and the database CIDR. ECS ingress originates only at the restricted HTTPS ALB. ECS outbound 443 remains broad for registry/log/secret access; VPC endpoints can narrow this. RDS is private, encrypted and backed up. App-to-RDS uses TLS `require`; deploy a CA bundle and `verify-full` to add server identity verification. ALB-to-task traffic is HTTP within the VPC.

The chaos CLI deliberately exposes process exit after insert; the HTTP API never accepts a fault parameter. This is an operator tool with database credentials, not an autonomous repair agent. It retries exact inputs and never edits financial records. Optional deployment workflows require environment protection, an OIDC trust restricted to this repository's production environment, and an IAM role limited to the intended ECS service/task family, image repository and PassRole execution role. No persistent AWS access key is needed.

Report issues privately through the repository's security reporting channel when configured. Do not attach real customer payloads or credentials to issues. No real customer data is included.
